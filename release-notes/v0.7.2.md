# v0.7.2：修复新版宿主上的成员派发故障

发布日期：2026-10-17

## 问题

DSH `0.2.1-alpha.2` 上，团队计划可以建立和批准，但成员启动失败，任务无法进入执行。日志中的错误为 `Cannot read properties of undefined (reading 'call')`。

新版 `@deepseek-ai/dsh-subagent` 移除了 `start` / `startContinuable`，改用 `startActivation`。旧插件的委派守卫仍无条件包装旧方法，导致启动时调用不存在的函数。此前宿主白名单更新只解决了安装与插件行兼容声明，没有覆盖这条运行时启动路径。

## 修复

- 在宿主兼容层集中选择成员启动接口：优先 `startActivation`，旧宿主回退到 `startContinuable`；两者都缺失时给出明确错误。
- 新版入口显式使用 `delivery: 'parent'`，保留持久子会话、父级通知与恢复语义；不切换为临时调用方交付。
- 委派守卫只包装真实存在的方法，覆盖新版入口，不再伪造旧方法；保留原方法的 `this`。
- 停止成员时优先使用新版 `drainChildren`，旧宿主回退到 `drainContinuableChildren`；仍只停止指定成员子树，等待递归停止完成，保留失败上抛，避免重派或归档误报成功。
- 保持成员工具过滤、成员相对委派深度预算、已退出成员与团队停机的准入限制；热重载卸载后还原原始方法描述符。

- 成员最终模型路由及备用路由遵守当前会话捕获的子代理模型白名单，越界在子会话创建前拒绝；省略参数也不再继承白名单外的队长模型。不自动挑选替代模型，无捕获策略的旧宿主保持原有行为。
- 通过 `ctx.get('sessionProjections')` 读取可选投影服务，服务缺失时回退会话持久事件；避免在真实 Cordis 插件上下文中直接读取未注入服务导致建队失败。

## 回归覆盖

新增启动、停止和模型策略回归，覆盖仅有新版 API 的成员启动、嵌套守卫卸载、成员委派预算与停机检查、缺失启动和停止契约的显式错误。模型策略测试覆盖显式选择、继承、备用路由、宿主投影、损坏策略、投影缺失时的持久日志恢复，以及旧宿主无策略行为；真实 Cordis 上下文分别验证可选服务存在与缺失。新增 `--activation-harness` 生命周期矩阵，并挂入 `verify:harness-contract`；原有旧版、modern 和 delivery 矩阵继续执行。

Windows / DSH Desktop 内置 `0.2.1-alpha.2` 的本机验收已实际通过计划创建与 Web 批准、成员领取与状态更新、32/32 回归测试、父级回报及工具归档。独立读取成员原始持久请求头，确认实际使用预选 `qwen-f/qodercn/qfmodel` 与 `low` 推理档位，未继承队长模型；没有修改其他团队数据。该结果不替代其他宿主与平台的 CI 矩阵。

源码与产物同步更新。发布流程继续要求 Ubuntu / Windows 静态检查及支持清单中的全部真实宿主验收通过，然后发布同一份候选包；推荐宿主仍为 `0.2.0-rc.2`，不扩大未知版本的支持范围。

## 升级

```sh
dsh plugin --profile <profile> add dsh-agent-teams-fish@0.7.2
```

升级后重启 DSH，使新的宿主端模块生效。无需修改团队记录或迁移配置；已失败的派发需在插件重新加载后显式重试，本版本不自动恢复已失败任务，也不会擅自恢复用户暂停的团队。
