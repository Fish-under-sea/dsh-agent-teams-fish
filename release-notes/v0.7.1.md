# dsh-agent-teams-fish v0.7.1

**修复「可选字段填空串就建不起团队」**：把内联计划（inline plan）里所有可选文本字段的 `""` / 纯空白按**未提供**处理，与 `add_member` / `edit_plan` 已有的口径统一。

另修两处会打红 `pnpm verify` 的问题：`#161` 的毫秒容差过小（Windows 上约一半概率误判），以及符号链接用例在无权限主机上不会跳过。

## 症状

某个会话里 `agent_teams_create` 连续失败 **34 次、0 次成功**，另一个会话 **14 次、0 次成功**，两个代理一个都没启动。报错在两条之间反复：

```text
Error: profiles.inline-plan.members[0].tool_policy must not be empty     (x15)
Error: profiles.inline-plan.members[0].provider must not be empty        (x6)
Error: profiles.inline-plan.members[0].model must not be empty
Error: profiles.inline-plan.members[0].reasoning_effort must not be empty
Error: unknown tool policy "default" (no toolPolicies are configured in this deployment)
Error: AgentTeams profile "inline-plan" has no members
```

同一个习惯还在**另外五个工具**上一致复发，证明这是调用方行为、不是某一个工具的契约：

```text
Error: `provider` must be non-empty                    (list_subagent_models)
Error: working-directory: cd must not be empty         (working_directory)
Error: include must be a non-empty glob when given     (grep)
Error: invalid justification: expected a non-empty sentence   (pwsh / edit)
```

## 根因

队长模型把**每一个可选参数都填成空字符串**，而不是省略它们。模型自己的推理记录写得很直白：

> "It seems I'm filling in all fields without realizing it! The tools I need require all parameters, even the optional ones, to work correctly."
> "I'm thinking through whether we can omit keys in the tool call."

工具 schema 里这些字段确实是可选的（`required` 只有 `["name"]`，且没有任何 `strict` / `default` 约束），所以这不是 schema 逼出来的，是模型的调用习惯。而插件侧**两条路径的口径不一致**：

| 路径 | 归一化函数 | `""` 的结果 |
|---|---|---|
| `add_member` / `edit_plan` | `trimmedOptional`（`src/tools.ts:309`） | 洗成 `undefined`，**放行** |
| inline plan（`agent_teams_create`） | `optionalNonEmptyString`（`src/profiles.ts`） | 抛 `must not be empty`，**必失败** |

`agent_teams_create` 的**顶层** `profile` 早已做了空串归一（`src/tools.ts:1002`，注释写明 "Some models materialize optional parameters as `""` instead of omitting them (issue #99)"），但**内联计划内部的成员字段没有**——缺口就在这里。

于是模型陷入死循环：填 `""` 撞空串校验 → 改填字面量 `"default"` 撞未配置的 `toolPolicies` → 回到 `""`，反复十余次后放弃。**这不是模型不可用，也不是工具缺失**：同一台机器上，只要可选字段省略不填，`agent_teams_create` 一次即成功。

## 修法

只改一处——`src/profiles.ts` 的 `optionalNonEmptyString`：

```diff
 function optionalNonEmptyString(value: unknown, path: string): string | undefined {
   if (value === undefined) return undefined
   if (typeof value !== 'string') {
     throw new Error(`${path} must be a string`)
   }
   const trimmed = value.trim()
-  if (trimmed === '') {
-    throw new Error(`${path} must not be empty`)
-  }
+  if (trimmed === '') return undefined
   return trimmed
 }
```

这一处覆盖全部**可选**文本字段 —— 成员级 `role` / `provider` / `model` / `reasoning_effort` / `executionPrompt` / `tool_policy`，计划级 `description` / `protocol` / `executionPrompt`，任务级 `description`。**必填字段一律不动**：`requiredNonEmptyString` 仍然严格，`name` / `id` / `subject` / `fallback.provider` / `fallback.model` / 依赖项 id 填空串照旧报错，非字符串值照旧是硬错误，`provider` 给了 `model` 却没给仍然报 `sets provider without model`。

**为什么不是「补一句更友好的报错」**：空串本身不携带任何信息，它和「没填」在语义上就是同一件事。既然编辑路径已经这么判了，计划路径跟随同一口径比多写一条错误消息更简单，也更不容易再分叉。

## 附带修复：`#161` 判决漂移检测的毫秒容差过小

质量门的「这条判决还覆盖当前版本吗」在无摘要的旧版判决上只能靠文件 mtime 判断，而 `mtimeMs`（文件系统时钟）与 `updatedAt`（`Date.now()`，整毫秒）**来自两个不同的时钟**。Windows 上文件系统时钟会**领先**进程时钟：40 万次写入实测 p99 1.7ms、最坏 2.2ms（含 `Date.now()` 的 1ms 截断）；8 路并发写盘压力下最坏 1.2ms。

原容差 `MTIME_TOLERANCE_MS = 1` 低于这个偏移，于是**判决之前写好的文件**会被读成「判决之后被修改」，报出假的

```text
lib/stats.js was modified after this verdict closed (file mtime is later than the verdict)
```

`scripts/quality-gates-content-bound.test.mjs` 的前置断言因此在 Windows 上约 **57.75%**（231/400 次实测）的概率失败；单跑常绿、与其他 6 个测试文件并发跑时约 3~4 次挂 1 次，正是这个原因。

容差改为 **4ms**：覆盖实测偏移并留余量，同时远小于任何真实的判决后编辑（回归测试用 10ms 真实等待来验证「判决后的写入必须被发现」）。改后同一探针 400 轮失败 **0/400**，测试连跑 **10/10** 全绿。

新增两个**确定性**回归用例（不依赖真实时钟抖动，任何平台都能验证容差）：把 mtime 人为设成 `updatedAt + 2.2ms` 必须仍判可交付；设成 `updatedAt + 500ms` 必须仍判漂移。

## 附带修复：符号链接用例在无权限主机上不跳过

`#174` 与 doctor 的两个用例要真的建符号链接，而 Windows 需要开发者模式或提权（否则 `EPERM`）。原来只有一处写了 `process.platform === 'win32' ? 'symlink probe' : false` 这种平台硬编码，另两处完全没跳过，于是在没有该权限的主机上必红。

改为统一的运行时探测 `scripts/symlink-support.mjs`（实际尝试建一次链接，`false` = 支持、字符串 = 跳过原因），三处用例共用：有开发者模式的 Windows 仍跑完整覆盖，无权限时以明确原因跳过，POSIX 永不跳过。

## 验证

新增回归测试 `scripts/inline-plan-blank-optional-tdd.mjs`（已挂进 `pnpm verify` 主链，另有 `pnpm verify:inline-plan-blank`），**23 项断言全绿**：

- **绿**：截图中那次失败调用的原样参数（成员六个可选键全是 `""`）现在可以建出计划，且六个字段全部归一为 absent；
- **绿**：纯空白 `"   "` 与空串同解；
- **绿**：真实值（`provider` / `model` / `tool_policy`）照常保留并 trim；
- **红（保持严格）**：空成员名、空任务 id、空 subject、空依赖 id、非字符串可选值、`provider` 无 `model`、`provider` 给值而 `model` 给空串 —— 七条都必须继续抛错。

## 关于「子代理调不动」

排查过程中一并确认：截图会话里 `subagent` / `subagent_fork` / `subagent_codex` / `subagent_claude_code` **一次都没有被调用过**，工具定义 70 个请求里 100% 在位。所以「调不动子代理」的真实形态是**模型没有发起调用**，加上它一旦发起就会沿用同样的空串习惯去填 `list_subagent_models` 的 `provider`（实测该调用确实被 `` `provider` must be non-empty `` 打回）。本版修掉的就是这条参数习惯的落地障碍。

> 顺带提示：这些会话的队长路由是 `gpt`（第三方中继），而 `subagent-model-selection-settings` 的 `allowedModels` 白名单只收录 `bailian-he` / `deepseek-f` / `kimi-f` / `qwen-f` / `glm-f` / `hy-f` / `mimo-f` / `en-f` / `cn-f` / `minimax-f`，**不含 `gpt`**。子代理若不显式指定路由，会从队长会话继承 `gpt`，从而撞上宿主的 `child LLM route "gpt/…" is not allowed for this Session`。这属于部署侧白名单配置，不是本插件的缺陷；要在这个路由上委派，请给子代理显式指定白名单内的 `provider` + `model`，或把 `gpt` 加入 `allowedModels`。
