# dsh-agent-teams-fish v0.4.3

**纯文档修正版**：功能与 [0.4.2](v0.4.2.md) **完全一致**，只把一处自相矛盾的 README 文案带上 npm。

## 为什么要单独发一版

0.4.2 修掉了「队长头像永远是 DeepSeek 那张」，README 里也把主说明改成了「队长**跟随自己的模型路由**」。但同一份 README 的「已知限制与踩过的坑」表里**漏改了一行**：

```
| **队长不跟随模型路由** | 面板快照里只有成员的 provider/model，没有队长的……
                         所以队长用文件覆盖，想自动跟随需给快照加字段 |
```

于是同一份文档里，「队长跟随路由」与「队长不跟随路由」并存 —— 而且那句「想自动跟随需给快照加字段」**描述的正是 0.4.2 已经做完的事**。

代码没问题（快照字段、宿主写入、客户端识别都已在 0.4.2 上线并验证），问题在于 **npm 包里的 README 在 `npm publish` 那一刻就被冻结，事后无法修改** —— 这是本仓库 `scripts/readme-version.mjs` 开头写明的约束，也是它存在的理由。仓库里的 README 已经修正（提交 `f7e1aa9`），但要让 **npm 页面**显示正确文案，只能再发一版。

## 本版改动

- `README.md` / `README.en.md`：把「已知限制」表里的「队长不跟随模型路由」改为「**（0.4.2 已修）**」，并说明修复方式（`TeamState` 新增 `captainProvider` / `captainModel`、快照实时值优先、老团队记录回落随包图）。
- 两份 README 的「本版新增了什么」表补一行，说明本次是文档修正。
- `package.json` 0.4.2 → **0.4.3**；README 的 `dsh-agent-teams-fish` 依赖示例同步到 `^0.4.3`。

## 兼容

**与 0.4.2 二进制等价** —— `lib/` 产物逐字节相同，没有一行运行时代码变化。升级到 0.4.3 与停留在 0.4.2 的行为没有区别；升上来只是为了让 npm 页面上的文档不再自相矛盾。

## 验证

```bash
node scripts/readme-version.mjs   # README 版本引用与 package.json 一致
node scripts/git-artifacts.mjs    # 构建产物戳与源码一致（本版未改源码）
```

## 升级

```bash
pnpm update dsh-agent-teams-fish
```

装完**重启 DSH**。若撞上 pnpm 的供应链静置期（新发布 24h 内），升法见 [v0.3.1](v0.3.1.md) 里的说明 —— 重建 lock 后 `pnpm install --config.minimumReleaseAge=0`。
